# H-Net probe on the T4 for CrowdGPT: plan (NOT_RUN)

Status: **plan only; nothing in this file has been measured.** Source: Hwang, Wang and Gu, "Dynamic Chunking for End-to-End
Hierarchical Sequence Modeling" (arXiv 2507.07955), read through a summary, not the full text or the code.

## Question

Can a learned, byte-level chunker reduce what HiveMind moves between nodes or spends per token on CrowdGPT (`hivemind/crowd-v1`)
prompts, on a T4? H-Net cannot be fine-tuned from a BPE model, so this is a measurement of the released checkpoints, not a
training proposal.

## Scheduling rule

The T4 VM serves live traffic and is governed by the BOINC core-node session. This probe runs only when that session accepts it
and only while serving is idle. It uses its own directory and virtualenv, never edits the governor, the HOLD file,
`/opt/hivemind/t4` or any `hivemind-*` unit, and stops at the first sign of router load.

## Measurements (each reported as measured or NOT_RUN)

| # | Measurement | Positive control | Negative control |
|---|-------------|------------------|------------------|
| 1 | Checkpoint loads on sm_75 (T4); record the exact error if the Mamba-2 kernels do not | a trivial forward on random bytes | n/a |
| 2 | Peak VRAM and bytes/s for generation, `hnet_1stage_L` | the same run for the Qwen model already served, same prompt | n/a |
| 3 | Bytes per chunk on four prompt sets: English, French, Python, Lean (n prompts and tokenizer named in the report) | whitespace-split word count as the reference boundary count | shuffled bytes of the same prompts: the chunk ratio must change, otherwise the router ignores content |
| 4 | Activation bytes crossing the encoder-to-main boundary per generated byte, versus hidden-state bytes per token at a BPE split | analytic count from the config | n/a |
| 5 | Held-out loss in bits per byte on CrowdGPT held-out text | the Qwen model's bits per byte on the same bytes (convert loss per token by tokens per byte) | a randomly initialised model with the same config |

## Decision rule (stated before the run)

Continue to a two-host pipeline-split test only if measurement 1 succeeds, measurement 2 fits in 8 GB, and measurement 4 shows at
least a 2x reduction in boundary bytes against the BPE split on at least two prompt sets. Otherwise record the numbers and park
the idea. The loss comparison in measurement 5 is context only: H-Net and Qwen differ in training data, so it is not a ranking.

## Not claimed

Nothing about decentralised pretraining of an H-Net, about gains for the bee/LoRA path (it does not apply), or about any speed
advantage; the paper's results are at its own scale and data.
