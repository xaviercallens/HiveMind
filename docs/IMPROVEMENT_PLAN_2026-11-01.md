## 2. New actions that need the owner (not PRs)

1. **The PR gatekeeper executes pull-request code on the host that runs it** (IP-73, R). It checks out each open PR into a worktree and runs that PR's own new test files, `lake build` and `paper/*.py` with the host environment, for every open PR, including non-owner PRs, and before the trust decision is applied. Decide whether to run test execution only for owner-authored PRs, or inside a sandbox (the host's bubblewrap is blocked by AppArmor today). Until then a malicious pull request can run code with the runner's privileges.
2. **Merges use `--admin` without `--match-head-commit`** (R, IP-119): a head pushed between the check and the merge is merged with the earlier approval.
3. **Review the personal contact data committed in the outreach script** (IP-125, R, values not repeated here): decide whether it should be removed from history.
4. **Decide the auto-merge flags of the community orchestrator** (IP-72, R): with `execute_live` and `auto_merge` it merges with `--admin` after scanning a synthetic patch, not the real diff.
